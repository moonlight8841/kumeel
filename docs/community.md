# مجتمع كميل والنشر الهجين

يستمر المالك في نشر محتوى المنصة التحريري من لوحة الإدارة. يكتب الأعضاء مساهماتهم في `/member`، وتظهر المواد التي تعتمدها الإدارة في `/community`. لا يغيّر نشر الدفتر مسودات المجتمع أو قراراته.

## التفعيل

نفّذ `supabase/community.sql` مرة واحدة في SQL Editor للمشروع `jigypvbqiuakdatkzoul`. الملف إضافي، داخل معاملة واحدة، وقابل لإعادة التنفيذ. لا يستبدل حساب الإدارة أو سياسات المنصة الحالية. يعتمد على `kumeel_is_secure_editor()` الموجود، لذا يتبع إعادة تفعيل MFA مستقبلًا تلقائيًا.

## دورة المساهمة

- `draft`: مسودة خاصة يمكن لصاحبها تعديلها.
- `pending`: نسخة ثابتة بانتظار قرار الإدارة.
- `published`: لقطة عامة مع اسم العرض والمصادر والتصريح بالمساعدة الآلية؛ دون بريد أو معرّف حساب أو ملاحظة مراجعة.
- `changes_requested`: نسخة خاصة مع سبب الإعادة يمكن تعديلها وإرسالها مجددًا.
- `rejected`: نسخة خاصة غير قابلة للنشر أو التحرير.

الإدارة تعتمد نص الكاتب كما أرسله، دون تغيير هويته أو تحريره بالنيابة عنه. طلب التعديل أو الحجب يحتاج سببًا. قرارات المراجعة تسجل في `kumeel_review_log`، المتاح للإدارة فقط. يعتمد الاعتماد على رقم النسخة؛ القرارات القديمة ترفض بدل الكتابة فوق تغيير أحدث.

## الحوار

الردود مرتبطة بالمواد المنشورة في المجتمع، وتبقى خاصة لصاحب الرد والإدارة إلى حين الاعتماد. حجب المادة يحجب ردودها؛ إعادة نشرها لا تعيد الردود تلقائيًا، بل تتطلب مراجعتها مجددًا. الواجهة تعرض حتى ١٠٠ رد معتمد لكل مادة. التفاعل هنا نصي مُراجع، ولا يشمل رسائل خاصة أو محادثة فورية.

## الحماية والحدود

كل تعديل يتم عبر RPC يتحقق من البريد المؤكّد وملكية النص، أو صلاحية الإدارة المحددة مسبقًا. لا تمنح الحسابات العادية كتابة مباشرة إلى الجداول أو اللقطات العامة. RLS يعزل المسودات؛ جداول عامة منفصلة تمنع تسريب الحقول الخاصة. جميع النصوص تُعرض كنصوص مهروبة، دون HTML من العضو.

حد يومي لكل حساب: ٥ مساهمات جديدة، ٢٠ ردًا، و١٠٠ عملية كتابة. العدادات تقفل داخل معاملة قاعدة البيانات لتعمل عبر جميع الأجهزة والخوادم. الحدود ليست بديلًا عن مراجعة إساءة الاستخدام. الحدود ترفض العملية كاملة دون حفظ جزئي.

النصوص غير المحفوظة تبقى في الذاكرة مع تحذير عند مغادرة الصفحة؛ لا تُكتب مسودات الأعضاء في مخزن مشترك للمتصفح. الحفظ السحابي يحتاج قاعدة البيانات المفعلة. لا تعرض الواجهة نجاحًا عند فشل الحفظ.

## التحقق

`npm run build`، `npm run lint`، `node scripts/test-platform.mjs`، و`node scripts/test-generate-idea.mjs`.

اختبار PostgreSQL المعزول:

```powershell
npm.cmd install --prefix artifacts/community-db @electric-sql/pglite@0.5.8 --ignore-scripts --no-audit --no-fund
node scripts/test-community-db.mjs
```

محرك الاختبار داخل `artifacts` فقط؛ ليس تبعية للواجهة أو قاعدة بيانات إنتاج. يغطي المنع والسماح للأدوار، خصوصية المسودات، تأكيد البريد، المراجعة، تعارض النسخ، السحب، إعادة النشر، والحدود اليومية. يبقى اختبار الإنتاج بعد تنفيذ SQL مطلوبًا.

لا توجد خدمة جديدة مدفوعة أو إرسال بريد جماعي أو اتصال جديد بخدمة توليد. تستخدم الإضافة حسابات Supabase الحالية.

## آراء القراء والمحاور

نفّذ `supabase/writing-dialogue.sql` بعد `community.sql`. الملف إضافي وقابل لإعادة التنفيذ ولا يعدّل دوال المجتمع.

- الأعضاء ذوو البريد المؤكد يكتبون رأيهم أسفل الكتابة عبر `kumeel_send_writing_response`. الرأي يُقبل فقط لمعرّف كتابة موجود في النسخة المنشورة، ويشترك مع ردود المجتمع في حد ٢٠ يوميًا.
- المراجعة من «مراجعة المجتمع» ← «آراء على الكتابات» عبر `kumeel_review_writing_response`، وتُسجّل بنوع `writing_response`.
- «المحاور» في الإدارة يحفظ الجلسات الخاصة في `kumeel_sparring` (المالك فقط). «انشر هذه الجولة» يضيف الاعتراض والجواب إلى `exchange` في المسودة؛ لا يظهر شيء للعموم قبل النشر المعتاد. الجولات لا تؤثر في بصمة الترجمة ولا تظهر في الصفحات الإنجليزية.
- قبل الإطلاق: تأكد أن `kumeel_published.content->'writings'` يحمل معرّفات الكتابات المعتمدة نفسها التي يعرضها الموقع. إن كانت القوالب القديمة ما زالت محفوظة، انشر مرة من الإدارة.

اختبار قاعدة البيانات المعزول في `scripts/test-community-db.mjs` يغطي هذا الملف أيضًا.
