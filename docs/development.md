# تطوير منصة كميل على Cloudflare Workers

## الوضع الحالي

التطبيق يعمل كـWorker باسم kumeel-platform في حساب الدومين 507f6fe5b3957bfe68fcc7f91534c3c3 بعد ربط النطاق في 2026-10-15. بقيت النسخة السابقة في الحساب 9308b41ae6796fc487cc95b6387e8295 دون تعديل. الواجهة React/Vite، والخادم في worker/index.mjs، والبيانات والمصادقة في Supabase. لم تُنقل قاعدة البيانات.

العنوان الرسمي: https://kumeelalnahab.com، وwww يتحول إليه مع الحفاظ على المسار والاستعلام. تفاصيل الربط والتحقق وحدود اختبار الدخول في [domain-binding.md](domain-binding.md).

## دورة التغيير

1. أنشئ فرع Git لكل ميزة، وحدد السلوك المطلوب ومعيار نجاحه.
2. شغّل `npm run dev` لتحرير الواجهة بسرعة. شغّل `npm run build` ثم `npm run dev:cloudflare` للتحقق من النسخة المبنية داخل بيئة Workers المحلية. أعد البناء بعد تعديل الملفات المصدرية؛ خادم Workers هنا لا يحل محل إعادة بناء Vite.
3. شغّل `npm run verify`: يفحص الشفرة، ويبني التطبيق، ويشغّل الاختبارات وفحص المحتوى وحزمة Workers، دون نشر أو كتابة بيانات اختبار عن بعد.
4. راجع التغيير، ثم انشر بـ`npm run deploy:cloudflare` بعد تسجيل أداة Wrangler في الحساب الصحيح. هذا الأمر يعيد التحقق قبل النشر. الاتصال المتاح داخل المحادثة يتيح النشر عبر API أيضًا، لكنه لا يسجّل Wrangler تلقائيًا.
5. شغّل `npm run test:published` من Windows للتحقق من النسخة العامة باستخدام curl.exe والتحقق من TLS. دخول المالك وحفظ المحتوى وإرساله يحتاجان تحققًا فعليًا مستقلًا.

أُعدّ ملف `.github/workflows/checks.yml` للفحص عند طلب دمج أو تحديث main. لا يعمل على GitHub حتى تُرفع الملفات إلى المستودع؛ ولا ينشر تلقائيًا أو يحتاج أسرار Cloudflare. لا تفترض نجاح الفحص الخارجي من نجاحه محليًا.

## البيئة والأسرار

أمر dev:cloudflare يمنع التحميل التلقائي لملفات .env العامة، حتى لا تدخل مفاتيح GitHub والإدارة إلى بيئة Worker. عند الحاجة انسخ .dev.vars.example إلى .dev.vars وأضف فقط أسرار التطوير اللازمة. الملف مستبعد من Git.

محاكاة Workers محليًا ليست عزلًا لقاعدة البيانات: المشروع يشير حاليًا إلى Supabase الإنتاجي. لا تختبر عمليات تعديل تجريبية بحساب المالك ضد بيانات الإنتاج. استخدم مشروع Supabase منفصلًا قبل اختبار تدفقات الكتابة أو الدفع على نطاق واسع. الاختبارات الآلية الحالية تحاكي الشبكة حيث يلزم.

تبقى مفاتيح مزوّد الذكاء الاصطناعي اختيارية وتخضع لتكاليفها المستقلة. لا تُفعّل خططًا مدفوعة أو دفعًا حقيقيًا أثناء التطوير.

## التحديث والرجوع

من لوحة Cloudflare: افتح Worker ثم Deployments، واختر الإصدار المطلوب للرجوع. عبر Wrangler راجع `npx wrangler versions list` ثم `npx wrangler rollback <version-id>` واستهدف الحساب الموجود في wrangler.jsonc. الرجوع للكود لا يستعيد بيانات Supabase؛ صدّر نسخة احتياطية قبل تغييرات البيانات أو ترحيلها.

## ترتيب التطوير التالي

1. إكمال روابط تحويل البريد وتجربة الدخول والاستعادة وصلاحيات المالك على العنوان الحالي.
2. تثبيت إدارة المحتوى والنسخ الاحتياطية والتحقق من الهاتف والأداء.
3. بناء الدورات: المساقات والدروس والتقدم والصلاحيات، مع محتوى مجاني أولًا.
4. إضافة الدفع والاشتراكات في بيئة اختبار، والتحقق من إشعارات الدفع والإلغاء والاسترداد والوصول للمحتوى.
5. ربط kumeelalnahab.com بعد نقله، ثم تحديث SITE_URL وروابط Auth وTurnstile وفحص الموقع مجددًا.

المراجع: [النشر من GitHub](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/)، [أسرار التطوير](https://developers.cloudflare.com/workers/local-development/environment-variables/).
