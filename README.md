# كميل ال نهاب — مساحة شخصية

منصة عربية RTL للفلسفة والعلم والثقافة: تعريف بكميل ال نهاب، وكتابات، ومرصد أفكار، وحكمة بصرية، ودروس مرئية، ومجلس حوار. React + TypeScript + Vite، مع Supabase للحفظ والمصادقة والملفات وVercel لعرض HTML من الخادم.

## التشغيل والتحقق

تتضمن المنصة مساحة اكتشاف للعلوم والثقافة والتجارب، مع بحث وتصفية وفتح النصوص وحفظ قائمة قراءة محلية، وتحدّي معرفة من ثلاثة أسئلة مع تفسير الإجابات والنتيجة وإعادة المحاولة. المحتوى التمهيدي في `src/components/Explore.tsx`، ولا يُنسب إلى صاحب الموقع. قائمة القراءة تُحفظ على المتصفح المستخدم.

## مرصد الأفكار ومجلس الحوار

- `src/content.ts`: نموذج المحتوى، ويقبل المحتوى القديم دون `ideas` أو `sessions`. الحقول الجديدة اختيارية، ولا تتطلب ترحيل قاعدة البيانات؛ تُحفظ ضمن JSON المحتوى الحالي.
- `src/components/ThoughtEditor.tsx`: إضافة الأفكار وتعديلها مع السؤال والاعتراض والمصدر، وإضافة سياق للصورة أو الفيديو، وإعلان موعد اللقاء أو تعديله وإلغاؤه. الملفات القديمة تبقى محفوظة في الدفتر، ولا تظهر في المرصد قبل إضافة غرضها ووصفها.
- `src/components/ThoughtSpace.tsx`: مرصد الأفكار ومختبر الافتراضات الخاص بالمتصفح ومواعيد الحوار. التمرين لا يُرفع إلى الخادم. الجلسات ليست خدمة مؤتمرات داخلية؛ تُفتح عبر رابط Google Meet أو YouTube المعتمد.
- `src/lib/calendar.ts`: ملف ICS بتوقيت UTC مكافئ لموعد الرياض، مع حماية الأسطر وطيّ النص العربي حسب طول UTF-8.
- رفع ملف إلى Storage لا يُنشئ درسًا مكتملًا؛ أضف وصفه ومصدره من محرر المواد المرئية، ثم انشر المسودة. حد الرفع السحابي ٥٠ ميغابايت كما في الإعداد الحالي.

## صفحات المحتوى والبحث

`/about` و`/observatory` و`/salon`، ولكل فكرة أو كتابة أو مادة مرئية رابط مستقل: `/ideas/:id` و`/writings/:id` و`/media/:id`. ملف `src/lib/pages.ts` يجمع بيانات العنوان والوصف وcanonical وJSON-LD وقائمة الصفحات العامة. تخرج الصفحات المنشورة من الخادم بمحتواها النصي، وتُرجع المادة المفقودة HTTP 404. النماذج التجريبية تحمل `noindex` وتُستبعد من sitemap؛ معاينات المسودات في المتصفح تحمل `noindex` أيضًا.

تُضاف بيانات `VideoObject` عندما يُدخل المالك الصورة المصغّرة وتاريخ النشر الأصلي، دون اختلاق تاريخ. فيديو YouTube يُضمّن من `youtube-nocookie.com` بمعرّف صالح؛ الروابط الأخرى تُشغّل كملفات فيديو مباشرة. تحميل YouTube واختبار جودة اللقاء الفعلي يتطلبان اتصالًا بالمنصة.

عند النشر، اضبط `SITE_URL` على عنوان HTTPS الرسمي، أو يُستخدم `VERCEL_PROJECT_PRODUCTION_URL`. هذا يثبّت canonical وهوية الشخص وروابط sitemap، ويضيف عنوان sitemap إلى robots.txt. إعداد البحث لا يضمن الفهرسة أو الترتيب أو الظهور في كل استعلام. بعد نشر المواد الأصلية، أضف النطاق إلى Google Search Console وافحص عينة من الصفحات وخريطة الموقع.

`npm.cmd test` يبني المشروع ويختبر التوافق، والتحقق من الروابط والمحتوى، وحماية HTML/JSON-LD، والتقويم، وSSR، واستجابات الصفحات وsitemap وrobots. تستخدم اختبارات API بيانات اختبار عند حد الشبكة ولا تكتب إلى Supabase.

على Windows استخدم `npm.cmd ci` ثم `npm.cmd run dev -- --host 127.0.0.1` إذا كانت سياسة PowerShell تمنع تشغيل `npm.ps1`.

Node.js 24. شغّل `npm ci` ثم `npm run dev`. `npm run lint` و`npm run build` للتحقق. البناء يولّد نسخة HTML ثابتة وSSR bundle. على Vercel تعرض `api/page.mjs` أحدث منشور من Supabase داخل HTML، مع بيانات hydration مهربة بأمان. التخزين المؤقت 60 ثانية مع stale-while-revalidate حتى 300 ثانية؛ عند تعذر قاعدة البيانات تُعرض النسخة المرفقة دون تخزين الاستجابة.

`npm run preview` يعاين النسخة الثابتة محليًا، ولا يشغّل Vercel Functions. لاختبار الخادم استخدم `vercel dev` أو استدعِ handler من Node بعد البناء.

## المحتوى والصلاحيات

- `src/content.ts`: محتوى البداية. النصوص والصور الحالية تجريبية ومعلّمة؛ ليست سيرة موثقة أو أعمالًا منسوبة إلى صاحب الموقع.
- `kumeel_published`: نسخة عامة واحدة. الزوار يقرؤون فقط؛ أعضاء `kumeel_editors` وحدهم يعدّلون حقل المحتوى. رقم النسخة يُحدّث من قاعدة البيانات ويمنع الكتابة فوق تحديث أحدث.
- `kumeel_drafts`: مسودة خاصة لكل مالك مخوّل. تسجيل الدخول وحده لا يمنح أي صلاحية نشر.
- `kumeel_editors`: قائمة المالكين. العضو يرى عضويته فقط ولا يستطيع إضافة نفسه أو الآخرين.
- `kumeel-media`: صور JPEG/PNG/WebP وفيديو MP4/WebM حتى 50 MiB. الملفات لها روابط عامة، ورفعها يتطلب عضوية مالك. لا ترفع مواد خاصة.

دفتر التحرير يبقي الحفظ المحلي والتصدير والاستيراد متاحًا. بعد تسجيل الدخول يمكن حفظ مسودة سحابية أو تحميلها، ورفع الملفات، ثم تأكيد نشر النسخة الحالية. حفظ حقل النبذة أو إضافة النص يحدّث المسودة فقط. يجب حفظ الحقول قبل النشر. الصور المحلية الصغيرة تتحول إلى Storage عند النشر.

## Supabase

المشروع المرتبط: `ktwugokiznarbnsvohzq`. `src/supabase-config.json` يحتوي URL ومفتاحًا عامًا فقط، وليس service_role أو رمز الإدارة. السياسات في `supabase/migrations/` تستخدم RLS وعضوية قاعدة البيانات ولا تثق ببيانات المستخدم القابلة للتعديل.

رمز الإدارة يُقرأ محليًا من `.env` باسم `supabase`؛ الملف مستبعد من Git والنشر. لا تُضمّن رمز الإدارة أو GitHub أو service_role في كود الواجهة. `scripts/supabase-admin.py` يستعمل Management API ويتيح فحص SQL والمستشارين. الترحيل في المستودع يحمل رقمًا مولّدًا من الخادم. لا تعِد تطبيق schema.sql على مشروع مُهيأ.

لتخويل المالك بعد التحقق من بريد حسابه الحالي في Supabase Auth، يضيف المسؤول UUID الحساب إلى `kumeel_editors` من قناة إدارية فقط. لا يُنشأ حساب أو كلمة مرور تلقائيًا، ولا توجد صلاحية نشر للحسابات العادية. يمكن تسجيل الدخول بكلمة مرور الحساب الحالي.

## Vercel والبحث

`vercel.json` يوجّه `/` إلى الخادم و`/sitemap.xml` إلى خريطة الموقع. اسم النطاق الرسمي يؤخذ من `VERCEL_PROJECT_PRODUCTION_URL` لتوليد canonical وog:url. توجد بيانات ProfilePage/Person ووصف عربي وrobots.txt. بعد اعتماد المواد الحقيقية يُثبت النطاق في Search Console؛ التهيئة لا تضمن الترتيب ولا تحذف نتائج الآخرين.

## الاختبارات

نجح البناء وESLint وفحص تبعيات التشغيل `npm audit --omit=dev`. اختبارات قاعدة البيانات في `supabase/tests/access.sql` تتحقق من القراءة العامة، منع غير المالك، عزل المسودات، صلاحيات الملفات، النشر ورقم النسخة. الاختبار يستخدم transaction وrollback ولا يترك مستخدمين أو ملفات أو تعديلًا على المنشور. تشغيله: `python3 scripts/supabase-admin.py query < supabase/tests/access.sql`.

اختُبرت الواجهة بـPlaywright على سطح المكتب والهاتف. راجع `docs/deployment.md` للحالة الفعلية للنشر وآخر تحقق.

## لوحة الإدارة

صفحة `/admin` مستقلة وغير قابلة للفهرسة، ولا تظهر في خريطة الموقع. تفتح أدوات التحرير بعد التحقق من عضوية الحساب في `kumeel_editors`؛ البريد المكتوب في النموذج ليس تفويضًا. سياسات RLS هي حاجز النشر الفعلي.

يمكن إدارة النبذة، عنوان ووصف وصورة الواجهة، الاقتباس، المظهر، بيانات التواصل وظهورها، وترتيب أقسام الرئيسية وإخفائها. نماذج مستقلة تحرّر الكتابات والأفكار والوسائط واللقاءات ومقالات الاكتشاف وأسئلة التحدّي. المكتبة تدعم الترتيب والإزالة والتراجع عن آخر إزالة ما لم تُجرَ تغييرات أخرى. النسخ الاحتياطية تدعم JSON والتحقق قبل الاستيراد. حفظ النموذج يحفظ مسودة المتصفح؛ النشر السحابي إجراء منفصل يتطلب صلاحية المالك ومراجعة النسخة.

### تفعيل المالك عند استعادة اتصال Supabase

لم يُفعّل حساب المالك أثناء هذه المرحلة: اتصال الأداة لا يملك إذن المشروع والرمز الإداري المحلي أعاد 401. لا توجد كلمات مرور أو صلاحيات مفترضة في الواجهة.

1. في إعدادات Auth فعّل Email provider وأضف عنوان `/admin` المحلي والإنتاجي إلى قائمة عناوين التحويل المسموحة.
2. من صفحة الإدارة اضغط «أرسل رابط دخول إلى بريدي» واستخدم `kumeelalnahab@gmail.com` ثم افتح الرابط لتأكيد ملكيتك للبريد. إذا كان لديك حساب وكلمة مرور، يمكن الدخول بهما.
3. بعد التأكيد ينفّذ مسؤول موثوق ملف `supabase/activate-owner.sql` في SQL Editor. يرفض الملف التنفيذ ما لم يوجد حساب واحد بهذا البريد وبريد مؤكد، ثم يمنحه إدارة المحتوى ويعرض نتيجة التحقق. الملف جاهز للمراجعة ولم يُنفّذ على المشروع.
4. أعد الدخول وتحقق من ظهور الأدوات ومن نجاح حفظ مسودة سحابية ونشر نسخة مراجعة. لا تستخدم service-role في المتصفح ولا تضف صلاحيات اعتمادًا على user_metadata.
